# Validation and Reliability Audit

This document records the Step 10 audit of all validation and reliability rules in **Mini ClassBuild**.
Each rule is grouped by functional area, marked with its enforcement status, and linked to the model, validator, or function that enforces it.

---

## 1. Course Outline Rules

| Rule | Status | Enforced By | Description |
|---|---|---|---|
| Required fields | Enforced (Stage 1) | `CourseOutline`, `LessonOutline` | Title, description, difficulty, objectives, and lessons cannot be empty. |
| Difficulty match | Enforced (Stage 1) | `CourseOutline.check_matches_request` | Must match the requested difficulty level (`Beginner`, `Intermediate`, `Advanced`). |
| Lesson count | Enforced (Stage 1) | `CourseOutline.check_matches_request` | Number of lessons must match the user's requested count (1–8). |
| Sequential numbers | Enforced (Stage 1) | `CourseOutline.check_lesson_numbers` | Lesson numbers must be strictly sequential (1, 2, 3...) with no gaps or reordering. |
| Unique lesson titles | **Added in Step 10** | `CourseOutline.check_unique_lesson_titles` | Lesson titles must not be duplicates (compared case-insensitively and ignoring whitespace). |

## 2. Lesson Content Rules

| Rule | Status | Enforced By | Description |
|---|---|---|---|
| Lesson number & title | Enforced (Stage 1) | `LessonContent.check_matches_selected_lesson` | Generated lesson must match the requested number and title from outline. |
| Section count | Enforced (Stage 1) | `LessonContent.sections` | Must contain between 2 and 4 sections. |
| Exercise count | Enforced (Stage 1) | `LessonContent.exercises` | Must contain exactly 2 exercises with hints. |
| No citations without PDF | Enforced (Stage 2) | `LessonContent.check_citations` | Ordinary lessons must not contain any source references. |
| Grounded lesson citation | Enforced (Stage 2) | `LessonContent.check_citations` | PDF-grounded lessons must cite at least one passage. |
| No uncited page mentions | **Added in Step 10** | `GroundedLessonGenerator.generate_lesson` (`uncited_page_mentions`) | Any page number mentioned in text (e.g. 'page 3') must be among the cited pages. |

---

## 3. Quiz & Assessment Rules

| Rule | Status | Enforced By | Description |
|---|---|---|---|
| Question count | Enforced (Stage 1) | `Quiz.questions` | A quiz must contain exactly 5 questions. |
| Distinct options | Enforced (Stage 1) | `Question.options_must_be_distinct` | All 4 options in a question must be distinct. |
| Distinct questions | Enforced (Stage 1) | `Quiz.questions_must_be_distinct` | No two questions in a quiz may have the same prompt. |
| Correct answer bounds | Enforced (Stage 1) | `Question.correct_answer` | Correct answer must be an integer index between 0 and 3. |
| Lesson alignment | Enforced (Stage 1) | `Quiz.check_matches_selected_lesson` | Quiz number and title must match the outline lesson. |

---

## 4. RAG & Retrieval Rules

| Rule | Status | Enforced By | Description |
|---|---|---|---|
| PDF size & format | Enforced (Stage 2) | `validate_pdf_upload` | Only `.pdf` files, non-empty, under 10 MB with valid `%PDF` header. |
| Similarity threshold | Enforced (Stage 2) | `select_evidence` (`MIN_PASSAGE_SIMILARITY`) | Retrieved passages below 0.30 similarity are discarded. |
| Insufficient evidence | Enforced (Stage 2) | `InsufficientEvidenceError` | When evidence is insufficient, fails honestly without hallucinations or unwanted LLM calls. |
| Untrusted passage data | Enforced (Stage 2) | `format_reference_passages`, Streamlit UI | PDF text is treated as data, never rendered as Markdown or instructions. |
| Verified sources | Enforced (Stage 2) | `to_source_reference`, `LessonContent` | Source references come from retrieval vectors, never generated by the LLM. |

## 5. Error Handling & Reliability

| Rule | Status | Enforced By | Description |
|---|---|---|---|
| Bounded SDK retries | **Added in Step 10** | `GroqClient.__init__`, `classbuild.config` | SDK automatic retries bounded by `GROQ_MAX_RETRIES` (default 1, range 0–3). |
| Non-retryable errors | Enforced (Stage 1) | `GroqClient._create` | 400, 401, 403, and 404 client errors are never retried. |
| JSON generation retry | Enforced (Stage 1) | `generate_validated` (`MAX_ATTEMPTS = 2`) | Exactly one retry on invalid JSON or validation failure. |
| API key redaction | **Added in Step 10** | `redact_secrets`, `GroqClient._error_detail` | Any string matching `gsk_*` is redacted to `[redacted]` before display. |
| State preservation | **Added in Step 10** | `app.render_form` | Previous valid course remains visible and intact if a new request fails. |

## 6. Persistence & Safety

| Rule | Status | Enforced By | Description |
|---|---|---|---|
| Safe course IDs | **Added in Step 11** | `CourseStore.path_for` | Only 32-hex-character IDs are allowed; paths cannot escape `saved_courses/`. |
| Atomic writes | **Added in Step 11** | `CourseStore.save` | Writes to a temp file first, then uses `os.replace` to prevent corrupted partial files. |
| File size limit | **Added in Step 11** | `CourseStore` (`MAX_COURSE_FILE_BYTES`) | Files over 2 MB are rejected. |
| Schema validation | **Added in Step 11** | `CourseStore.load`, `SavedCourse` | Every saved file is validated against Pydantic models upon reading and writing. |
| Secret exclusion | **Added in Step 11** | `SavedCourse` schema | No API keys, chats, submitted answers, PDF binaries or embeddings are saved to disk. |
| PDF fingerprint check | **Added in Step 11** | `app.pdf_features_allowed` | Loaded PDF courses require the exact original PDF fingerprint to unlock PDF features. |
